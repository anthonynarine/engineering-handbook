# Financial libraries — source notes

Recorded 2026-10-21 for the "Financial libraries" section (Plaid and Stripe lessons).

## Owner projects inspected

- Moneta Plaid design documents (PLAID_SANDBOX, PLAID_PRODUCTION_PREPARATION, TRANSACTIONS). Link tokens bound to a short-lived attempt for one member and household; public token exchanged server-side; access tokens Fernet-encrypted at rest; update mode for reconnect; disconnect marks local state first, then revokes upstream with retry; environment provenance tags (sandbox versus production) on connections and data; separate `PLAID_SECRET` and `PLAID_PRODUCTION_SECRET`; production behind a release gate. `/transactions/sync` with up to 500 records per page, original cursor preserved until every page succeeds, restart after `TRANSACTIONS_SYNC_MUTATION_DURING_PAGINATION`, removed records become tombstones (handles pending-to-posted replacement), provider reads outside database locks with a recheck under a row lock before commit. Amounts stored as decimals with ROUND_HALF_EVEN; positive means money out, following Plaid. Known limit: an exchange that succeeds at Plaid but fails before the database commit can orphan an Item. As of 2026-10-21 the owner authorized a production pilot; live bank acceptance was still pending. No webhook receiver or scheduler yet; sync is manual.
- EstateIQ subscriptions app: dj-stripe 2.10.4, stripe-python 11.3.0. Webhook handlers for `customer.subscription.created/updated/deleted` and `invoice.payment_failed`, idempotent upserts, organization resolved from subscription metadata set at checkout, Stripe treated as the source of truth, mirror synced from Stripe when a webhook arrives first. The handler reads `current_period_end` from the subscription object, which API version 2025-03-31.basil removed (moved to subscription items).

## Official documentation consulted

- Plaid: Link overview (link_token from `/link/token/create`, expires after 4 hours or 30 minutes in update mode; `public_token` from `onSuccess`; `/item/public_token/exchange` returns `access_token` and `item_id`), update mode, OAuth guide, Item removal, Transactions API (`/transactions/sync` cursor, `count` 1–500 default 100, `added`/`modified`/`removed`/`next_cursor`/`has_more`, restart pagination from the original cursor on mutation errors, `SYNC_UPDATES_AVAILABLE` webhook, `pending` and `pending_transaction_id`), webhook verification (`Plaid-Verification` JWT, ES256 only, key from `/webhook_verification_key/get` by `kid`, reject `iat` older than 5 minutes, SHA-256 of the raw body compared with `request_body_sha256` in constant time).
- Stripe: webhooks (verify `Stripe-Signature` with the endpoint's `whsec_` secret over the raw body; library default tolerance 5 minutes; duplicates possible, track event IDs; ordering not guaranteed; return 2xx quickly and process asynchronously; live-mode retries for up to three days; exempt the route from CSRF; thin events recommended for new integrations), idempotent requests (`Idempotency-Key`, results saved for v1 POST requests, keys may be pruned after 24 hours, parameter mismatch errors), subscriptions overview (statuses trialing, active, incomplete, incomplete_expired, past_due, canceled, unpaid, paused; provision on active or entitlements; `invoice.paid` and `invoice.payment_failed`), changelog 2025-03-31.basil (subscription-level `current_period_start/end` removed, now on subscription items).

These lessons teach concepts and patterns. They are not evidence that any described production integration has passed live acceptance.
