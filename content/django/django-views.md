## Pick the smallest useful abstraction

| Interface | Good fit | Tradeoff |
| --- | --- | --- |
| Django function view | A small HTML response or framework health endpoint | You handle HTTP behavior directly |
| DRF `@api_view` function | A small JSON operation with explicit methods | Keep serializer and permission policy explicit |
| DRF `APIView` | A command with distinct request handling | More orchestration code is written by hand |
| DRF generic view | Standard list, detail or create behavior | Learn its hooks and queryset behavior |
| DRF ViewSet plus router | Several operations around one resource | Routes and actions become less visible locally |

Function-based does not mean insecure or unmaintainable. Class-based does not automatically mean well-structured. Readability, repeated behavior and the endpoint's contract decide.

## Keep commands recognizable

`POST /reports/{id}/generate/` is a workflow command, not arbitrary model editing. An APIView or a carefully scoped ViewSet action can validate its input and call a service. Use serializer validation for input shape, permission checks for authority and a service for the durable transition.

A ModelViewSet exposes multiple operations by default. If a resource should only be read, use a read-only variant or explicit mixins. Audit the resulting URL and method table, including custom actions.

## Scoping is required with every style

Use a trusted, filtered queryset before looking up an object. List access does not automatically run an object-level permission check on each row. Creation has no existing object on which to run that check. Enforce list scope, create scope and related-object ownership explicitly.

## How I apply it

The [Tasks starter](/guide/django-first-api) uses a ViewSet because its contract is straightforward owner-scoped CRUD. The [Reports API](/guide/reports-api) shows explicit operations around a workflow. Both should delegate shared rules rather than duplicating them across HTTP handlers.

Verify allowed methods, unauthorized requests, foreign IDs, validation failures and the exact routes generated by routers. Consult the [ViewSet reference](https://www.django-rest-framework.org/api-guide/viewsets/) for action wiring.
